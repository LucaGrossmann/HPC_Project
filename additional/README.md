# `additional/` — Part 5: Julia (additional paradigm)

Single-file Julia implementation using only the standard library
(`LinearAlgebra`, `Random`, `Printf`). The `mode3` helper handles
both forward and inverse transforms via `reshape` → `*` → `reshape`,
calling BLAS `dgemm` underneath. The per-slice SVD loop calls
`svd` (LAPACK `dgesdd`) and assembles `S_hat` via the stdlib
`Diagonal` wrapper.

The implementation is ~130 lines vs. ~350 in the C++ baseline. JIT
warmup is amortized by an untimed first call before the timed loop.

## Layout

| File | Role |
|---|---|
| `tsvdm.jl` | Algorithm + driver in one file: `mode3` (forward and inverse via reshape→matmul→reshape), per-slice `svd` loop, `Diagonal`-based `S_hat` assembly, plus an untimed warmup call to amortize JIT cost. |
| `Project.toml` | Pinned standard-library and stdlib-extension package versions for reproducibility (Julia uses the package set provisioned in the `CS-2050` Spack env). |
| `submit.slurm` | Single-node, single-thread CPU job. Runs a 3-size sweep (`64³`, `256³`, `512×512×256`) and a fixture cross-check against `serial/fixtures/medium.bin`. |
| `results/` | Per-Slurm-job stdout and `julia_size_scaling.pdf` generated by `report/plot_scaling.py`. |

## Run

```bash
[cluster]$ cd additional && sbatch submit.slurm
```

`submit.slurm` activates the `CS-2050` Spack env (which provisions
Julia), pins `OPENBLAS_NUM_THREADS=1` to match the other CPU
backends, then runs the size sweep and a fixture cross-check.

Output line format is identical to the C++ backends with an extra
`backend=julia` token, so `report/parse_results.py` picks it up
automatically.
